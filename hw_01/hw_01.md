# Part 1
## Determining L2 Cache Parameters

**Usage**: `./part1`

a. **Cache Block/Line Size** - 64 B. The cache block size was determined by allocating an 8 MB array and linearly iterating over the array multiple times in strides of 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, and 1024 bytes. Each of these iterations were measured using a microsecond timer. The largest difference in times was between 64 and 128 B since strides of 64 B or more required fetching a new block for every memory access. The results are shown below, with microseconds converted to ms for convenience:
![image](file:///Users/alextang/Code/RU/operating_systems/hw_01/part1a.jpg =600x)

b. **Cache Size** - 256 KB. The cache size was determined by guessing the cache size and allocating blocks of memory corresponding to these guesses. The guesses started 64 B, corresponding to the line size found in part a, and were doubled up to 4 MB.  Random indices in these blocks were repeatedly accessed many many times to throw off the hardware prefetching and these times were recorded. The cache size was determined to be 262144 B or 256 KB because the biggest spike in time access occurred between 256 KB and 512 KB. The results are shown below:
![image](file:///Users/alextang/Code/RU/operating_systems/hw_01/part1b.jpg =600x)

c. **Cache Miss Penalty** - 0.0087 usec. Since the cache size was determined to be 256 KB from part b, two arrays were allocated, one of 256 KB and one of 512 KB (bigger than the cache size). Random indices in each of these arrays were accessed 10,000 times and the times recorded. The average access time in the 256 KB array was 0.0642 usec and the in the 512 KB array was 0.0729 usec. The reason this penalty is so small may be due to prefetching as well as the presence of an L3 cache.




# Part 2 
## Cost of fork()

**Usage**: `./part2 <size-in-MB>`

The program `./part2` loops 10,000 times to compute the average cost of a `fork()` call. First, an array of `<size-in-MB>` MB is allocated and initialized. After this, the loop is started and a timer is started. `fork()` is called and the parent waits for the child using `waitpid()`. Once the child returns, the timer is stopped and the parent records the time of this `fork()` call in usecs. Note that the time it takes for the child to return is included in order to allow consistent execution, i.e., the parent always waits for the child so the child always executes first. # Part 3
## The cost of communication through pipes

**Usage**: `./part3 <size-in-MB>`

The program `./part3` loops 1,000 times to compute the average cost of communication through two pipes, `p2c` (parent-to-child) and `c2p` (child-to-parent). In each iteration, `p2c` and `c2p` are initialized and `fork()` is called. First, the parent writes to `p2c` in chunks of 1024 bytes while the child reads from `p2c`. Next, the child writes the data received from `p2c` into `c2p`, while the parent reads `c2p`. Each of these iterations are timed and the average is taken at the end. The relationship between block size and time seems to be proportional; as the block size increases, the time or cost of communicating through the pipes increases linearly.
